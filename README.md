# Mazzacha CRM

Мини-CRM для кондитерской. Считает себестоимость изделий по составу и показывает затраты, выручку и прибыль за каждый день. Работает локально на одном компьютере, данные хранятся в одном файле.

## Что умеет

- **Продукты и склад.** Цена за определённый вес или количество («Мука — 8 сомони за 1000 г»), закупки, остатки, инвентаризация, журнал движения. Новая закупка обновляет текущую цену.
- **Изделия и полуфабрикаты.** Состав на партию с выходом («на 12 кусков уходит…»), упаковка, время работы. Одно изделие может входить в другое: крем в торт, целый торт в 12 кусков. Если себестоимость известна без расчёта, её можно указать вручную.
- **День.** Таблица «что приготовили, по какой цене, сколько продали» с колонками: количество, себестоимость за штуку, цена, продано, списано, остаток, затраты, потенциальная выручка, потенциальная прибыль, фактическая выручка. Непроданное переносится на следующие дни, где его можно продать или списать. Общие расходы дня (такси, аренда) вычитаются из прибыли.
- **Заказы и поставки в магазин.** Заказы видны прямо на экране «День» с кнопкой следующего шага: «В работу» → «Готов» → «Выдать» → «Оплата». В день готовности заказ списывает сырьё и записывает затраты и выручку. Оплаты вносятся отдельно, частями и в любой день, поэтому видно, кто сколько должен. Для магазина, который платит после продажи, есть отчёт «продано / вернули»: возврат уменьшает выручку дня отправки и становится остатком, который можно продать или списать. Поставку можно повторить в один клик.
- **Обзор.** Сегодня, неделя и месяц со сравнением с прошлым периодом, график за 30 дней, цель по прибыли на месяц, ближайшие заказы и долги.
- **Отчёты.** Сводка за период по дням и по изделиям, маржинальность изделий: прибыль за штуку, наценка, сколько штук нужно продать, чтобы партия окупилась.

## Запуск

Нужны [.NET 10 SDK](https://dotnet.microsoft.com/download/dotnet/10.0) и [Node.js](https://nodejs.org) 20 или новее.

Windows: дважды щёлкните `run.bat`. Программа соберётся при первом запуске и откроется в браузере.

Linux и macOS:

```bash
./run.sh
```

После запуска программа доступна по адресу <http://localhost:5080>. Пока окно с программой открыто, она работает; чтобы остановить, закройте окно или нажмите Ctrl+C.

Чтобы посмотреть программу на готовом примере (три дня продаж), запустите её на пустой базе с флагом `--seed-demo`:

```bash
./run.sh --seed-demo
```

## С чего начать

1. **Продукты и склад** → «Новый продукт». Заведите сырьё и упаковку с ценами.
2. **Изделия** → «Новое изделие». Укажите выход партии, цену продажи и состав. Себестоимость считается сразу.
3. **День**. Выберите изделие, укажите, сколько приготовили и сколько продали. «Продано» и «Списано» можно править прямо в таблице.

## Как считаются цифры

По строке дня:

| Показатель | Формула |
|---|---|
| Затраты | количество × себестоимость за штуку |
| Фактическая выручка | сумма продаж |
| Остаток | количество − продано − списано |
| Потенциальная выручка | фактическая выручка + остаток × цена |
| Потенциальная прибыль | потенциальная выручка − затраты |
| Прибыль с проданного | фактическая выручка − продано × себестоимость |

По дню:

- **Затраты дня** = затраты на всё приготовленное в этот день + общие расходы дня.
- **Выручка дня** = всё проданное в этот день, включая остатки прошлых дней и выданные заказы.
- **Прибыль дня** = выручка − затраты.
- **Заказ** целиком относится к дню готовности (для магазина — к дню отправки): в этот день его затраты и выручка.
- **Получено денег** = продажи с витрины + оплаты по заказам, пришедшие в этот день. Разница между выручкой заказов и оплатами — долги, они видны на «Дне», в «Заказах» (фильтр «Ждут оплаты») и у клиентов.

Себестоимость фиксируется в момент записи в день. Если продукт подорожал, уже записанные дни не меняются; пересчитать строку по новым ценам можно вручную в её меню. Закупки продуктов в затраты дня не входят (иначе сырьё посчиталось бы дважды), они видны в журнале склада.

## Где лежат данные

Все данные хранятся в одном файле SQLite. Его путь показан на странице «Настройки»:

- Windows: `%LOCALAPPDATA%\MazzachaCRM\mazzacha.db`
- Linux и macOS: `~/.local/share/MazzachaCRM/mazzacha.db`

Резервная копия — это копия этого файла, сделанная при закрытой программе. Другое место для файла задаётся параметром `Database:Path` в `src/MazzachaCRM.Api/appsettings.json` или переменной окружения `Database__Path`.

## Для разработчика

### Устройство

```
src/
  MazzachaCRM.Domain/          сущности, инварианты, расчёт себестоимости; без зависимостей
  MazzachaCRM.Application/     команды, запросы, обработчики, валидация
  MazzachaCRM.Infrastructure/  EF Core + SQLite, репозитории, миграции
  MazzachaCRM.Api/             ASP.NET Core Minimal API, раздаёт собранный фронтенд
tests/
  MazzachaCRM.Domain.Tests/        правила домена
  MazzachaCRM.Application.Tests/   сценарии целиком на SQLite в памяти
web/                           React + TypeScript + Vite + Mantine
```

- **Чистая архитектура.** Зависимости направлены внутрь: Api → Infrastructure → Application → Domain. Домен ни от чего не зависит.
- **DDD lite.** Агрегаты (`Ingredient`, `Product`, `ProductionBatch`, `Order` и другие) сами защищают свои правила: нельзя продать больше, чем осталось, нельзя включить изделие в собственный состав. Себестоимость считает доменный сервис `ProductCostCalculator`.
- **CQRS.** Команды меняют агрегаты через репозитории, изменения сохраняются одной транзакцией после обработчика. Запросы читают через `IReadDbContext` без отслеживания и возвращают DTO. Диспетчер собственный (`Application/Common/Dispatcher.cs`), перед обработчиком он запускает валидаторы FluentValidation.
- **Репозитории.** Интерфейсы лежат в домене рядом с агрегатами, реализации — в `Infrastructure/Persistence/Repositories`.
- **Ошибки.** `DomainException`, ошибки валидации и «не найдено» превращаются в ответы `ProblemDetails` с русским текстом (`Api/ApiExceptionHandler.cs`).

Каждый сценарий — один файл в `Application`: команда или запрос, валидатор и обработчик рядом.

### Режим разработки

Бэкенд и фронтенд запускаются отдельно, фронтенд пересобирается на лету и проксирует `/api` на бэкенд:

```bash
dotnet run --project src/MazzachaCRM.Api
```

```bash
cd web && npm install && npm run dev
```

Интерфейс в этом режиме открывается на <http://localhost:5173>. Описание API в формате OpenAPI: <http://localhost:5080/openapi/v1.json>.

### Тесты

```bash
dotnet test
```

В `DemoScenarioTests` лежит контрольный пример: три дня продаж, посчитанные вручную. Программа должна выдавать те же цифры.

### Миграции

```bash
dotnet ef migrations add <Название> --project src/MazzachaCRM.Infrastructure --startup-project src/MazzachaCRM.Api --output-dir Persistence/Migrations
```

Миграции применяются автоматически при запуске программы.
